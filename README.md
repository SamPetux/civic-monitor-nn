# Civic Monitor НН

**Платформа мониторинга и визуализации влияния новостных событий на гражданскую активность и настроения населения в социальных сетях.**

Civic Monitor собирает посты и комментарии из открытых сообществ ВКонтакте, определяет тональность сообщений с помощью моделей машинного обучения, привязывает их к административным районам города, выделяет обсуждаемые темы и всплески активности, а затем отображает всё это в интерактивном веб-интерфейсе с картой, графиками и таймлайном.

Платформа разработана и настроена на примере **Нижнего Новгорода** (8 административных районов), но спроектирована так, чтобы её можно было локализовать под любой другой город — см. раздел [«Локализация под свой город»](#локализация-под-свой-город).

---

## Возможности

- **Карта районов** — хороплет-карта города, окрашенная по уровню негативности обсуждений в каждом районе.
- **Дашборд района** — метрики (доля негатива, индекс негативности, активность, уникальные авторы, динамика относительно предыдущего периода), график тональности по дням и часам, топ обсуждаемых тем, лента комментариев с фильтрами по тональности и сообществам, экспорт PDF-отчёта.
- **Темы** — топ тем с долей негатива, donut-диаграмма распределения сообщений, тепловая карта всплесков «тема × дата».
- **Авторы** — рейтинг самых активных авторов с усреднённой тональностью и пометкой подозрительных (бот-подобных) аккаунтов, возможность исключить аккаунты из выборки.
- **Аналитический таймлайн** — стек-график тональности по всему городу с подвижным курсором, кнопкой воспроизведения и регулируемой скоростью, рейтинг районов и маркеры всплесков на шкале времени.
- **Фоновое обновление данных** — запуск парсинга прямо из интерфейса с настройкой периода, лимита и пересчёта аналитики.

## Архитектура

Платформа состоит из трёх контейнеров, оркестрируемых через Docker Compose:

```
┌──────────────────┐   HTTP/JSON   ┌────────────────────────┐    SQL    ┌──────────────┐
│  frontend        │ ────────────► │  api (FastAPI)         │ ────────► │  db          │
│  Next.js 14      │ ◄──────────── │  uvicorn :8000         │ ◄──────── │  PostgreSQL  │
│  :3000           │               │  REST поверх data_repo │           │  :5432       │
└──────────────────┘               └────────────────────────┘           └──────────────┘
```

| Сервис | Технологии | Назначение |
|--------|-----------|------------|
| `db` | PostgreSQL 15 | Хранилище постов, комментариев, групп, тем, всплесков |
| `api` | Python, FastAPI, SQLAlchemy | REST API поверх `modules/data_repo.py` |
| `frontend` | Next.js 14 (App Router), TypeScript, Tailwind CSS, MapLibre GL, Recharts | Веб-интерфейс |

**Конвейер обработки данных** (модули в `modules/`):

1. `vk_parser.py` — постраничная выгрузка постов и комментариев из ВКонтакте с учётом ограничений API.
2. `text_cleaner.py` — очистка текста и фильтрация рекламного шума.
3. `sentiment.py` — определение тональности моделью RuBERT-tiny2.
4. `geocoder.py` — привязка сообщений к районам по словарю ключевых слов (`district_keywords.py`).
5. `topics.py` — тематическое моделирование через BERTopic.
6. `burst_detector.py` — поиск всплесков активности по z-оценке.

Весь доступ к данным инкапсулирован в `modules/data_repo.py` — это единственная точка, через которую API читает агрегированные метрики. Парсер, ML-модули и интерфейс не зависят друг от друга напрямую.

## Быстрый старт

### Требования

- Docker и Docker Compose
- Сервисный токен ВКонтакте (для сбора данных) — получить можно в настройках сообщества или приложения VK

### Установка

```bash
git clone https://github.com/SamPetux/civic-monitor-nn.git
cd civic-monitor-nn
```

Создайте файл `.env` в корне (за основу возьмите `.env.example`):

```env
POSTGRES_DB=civic_monitor
POSTGRES_USER=civic_user
POSTGRES_PASSWORD=ваш_пароль
DATABASE_URL=postgresql+psycopg2://civic_user:ваш_пароль@db:5432/civic_monitor
VK_TOKEN=ваш_сервисный_токен_vk
```

Запустите все сервисы:

```bash
docker compose up -d
```

После запуска:

- Веб-интерфейс — http://localhost:3000
- API и Swagger-документация — http://localhost:8000/docs
- PostgreSQL — порт 5433 (для внешних подключений)

### Первичное наполнение данными

```bash
# Сбор постов и комментариев за последние 30 дней
docker compose exec api python parse.py --days 30

# Тематическое моделирование
docker compose exec api python analyze_topics.py --reset

# Поиск всплесков
docker compose exec api python detect_bursts.py --reset
```

Анализ тональности (требует моделей ML) удобнее запускать локально, если контейнер собран без torch:

```bash
DATABASE_URL=postgresql+psycopg2://civic_user:ваш_пароль@localhost:5433/civic_monitor \
  python analyze_sentiment.py --target comments
```

## Локализация под свой город

Платформа спроектирована так, чтобы её можно было перенастроить на другой город. Потребуется отредактировать несколько файлов:

### 1. Список сообществ для сбора

В конфигурации парсера укажите ID или короткие имена сообществ ВКонтакте вашего города (городские паблики, новостные группы, районные сообщества). Чем разнообразнее набор, тем полнее картина.

### 2. Административные районы

В `modules/districts.py` задайте список районов своего города — их идентификаторы и названия. Это базовый справочник, на который опирается весь интерфейс и легенда карты.

### 3. Словарь геопривязки

В `modules/district_keywords.py` для каждого района пропишите ключевые слова: названия микрорайонов, улиц, ориентиров, станций, характерных мест. По этому словарю сообщения привязываются к районам. Качество геопривязки напрямую зависит от полноты словаря.

### 4. Границы районов (GeoJSON)

Карта строится по файлу `data/districts.geojson` с границами районов в формате FeatureCollection. Подготовить его можно скриптом `prepare_data.py`, который выгружает административные границы из OpenStreetMap через библиотеку osmnx. Убедитесь, что идентификаторы районов в GeoJSON совпадают с идентификаторами в `modules/districts.py`.

### 5. Центр карты

В компоненте карты (`frontend/components/DistrictMap.tsx`) задайте координаты центра и масштаб под ваш город.

### 6. Модель тональности

Модель RuBERT-tiny2 обучена на русскоязычных текстах и подойдёт для любого русскоговорящего города без изменений. Для других языков потребуется заменить модель в `modules/sentiment.py` на подходящую.

После настройки этих файлов запустите парсинг и аналитику заново — платформа будет работать с данными вашего города.

## REST API

Документация всех эндпоинтов доступна через Swagger UI по адресу http://localhost:8000/docs после запуска.

Основные группы эндпоинтов:

- `GET /api/meta/period` — диапазон дат имеющихся данных
- `GET /api/meta/districts` — справочник районов
- `GET /api/meta/groups` — список сообществ
- `GET /api/geo/districts` — GeoJSON границ районов
- `GET /api/districts/metrics` — метрики по всем районам
- `GET /api/districts/{id}/comments` — комментарии района (с фильтрами и пагинацией)
- `GET /api/districts/{id}/sentiment` — динамика тональности
- `GET /api/districts/{id}/topics` — топ тем района
- `GET /api/districts/{id}/bursts` — всплески активности
- `GET /api/users/top` — рейтинг авторов
- `POST /api/reports/pdf` — генерация PDF-отчёта
- `POST /api/refresh/start` — запуск фонового обновления данных
